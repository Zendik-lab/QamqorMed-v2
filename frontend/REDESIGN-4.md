# QamqorMed — Overhaul 4.0: auth и профили

## Область этапа

После foundation 3.0 выполнен следующий этап: обновлены login, registration и профили PATIENT/DOCTOR/NURSE/ADMIN. Затем поступила задача Motion UI 5.0; её изменения и проверки описаны в `MOTION-5.md`. Полный Overhaul всех внутренних страниц ещё не завершён.

Аудит общей архитектуры находится в `REDESIGN-3.md`. Его описание admin profile как placeholder уже устарело: профиль администратора реализован в этом этапе. Маскирование ИИН и исправление AI autoscroll также выполнены в последующих этапах.

## Выполнено

- Общая двухколоночная auth-композиция с брендированным блоком и одноколоночной мобильной формой. Универсальный вход без выбора роли, controlled поля, показ пароля, busy/error состояния, блокировка повторной отправки и клавиатурный focus ошибки.
- Регистрация: группировка данных, обязательность полей, touched/submit validation, подтверждение пароля. Подсказки соответствуют текущему backend: 8–72 символа, буква и цифра. Login принимает существующие legacy-пароли без применения требований регистрации. Фиктивные SMS/recovery не добавлялись.
- Общие profile primitives: initials avatar, identity, role, facts, sections, shortcuts, states и настройки темы/языка/чтения. Безопасность использует уже существующий API смены пароля.
- Пациент: выделен самостоятельный lazy profile, явные просмотр/редактирование/сохранение/отмена, маскирование ИИН в сводке. Подопечные и медицинская сводка имеют независимые error/retry вместо подмены ошибки пустыми данными.
- Врач/медсестра: согласованные профили с реальными сведениями из API, связанной командой и расписанием; редактируются только разрешённые DTO-поля. Ошибка расписания не скрывает весь профиль.
- Admin: профиль из canonical auth user, существующие административные ссылки и настройки. Неподдерживаемое API редактирование admin не выдумывалось.
- Тексты новых экранов добавлены в RU/KK/EN. Dev-панель сохранена только в development. JWT, роли, session workflow, backend и PostgreSQL на этапе auth/profile не менялись.

## Проверки

- 7 account tests: границы пароля/телефона, независимые сообщения validation, legacy login, соответствие полям password API, маскирование ИИН, наличие переводов.
- Browser pass с отдельным loopback API: login/register validation, busy/server errors; профили всех четырёх ролей, read/edit/cancel/save; темы и языки; ширины 320/375/768/1024/1440.
- Production build и общие тесты прошли. Актуальные итоговые числа после Motion 5.0: 34 tests и 1085 ключей × 3 языка, подробности в `MOTION-5.md`.
- Настоящий пароль пользователя не менялся. Полный реальный Spring Boot/PostgreSQL медицинский цикл в этом проходе не проверен; синтетические UI TEST данные существовали только на временном локальном стенде.

## Остаток полного Overhaul

1. Последовательно модернизировать dashboard всех ролей и все внутренние разделы. В частности, отличать ошибки дополнительных запросов dashboard от реальных нулей/пустых ответов.
2. Пройти populated booking, МКБ-10, подготовку и завершение приёма, медицинские карты, документы и downloads на настоящем backend. Сохранять текущие правила времени, статусов и серверных прав.
3. Мигрировать остальные локальные modal/drawer/table/tab реализации на общую библиотеку без потери обработчиков; проверить подтверждения существующих опасных операций.
4. Довести клавиатурное удаление AI-истории и retry после ошибки. Учитывающий позицию autoscroll выполнен в 5.0; auth/Ollama не менялись.
5. Полный screen-reader/WCAG pass, все клинические формы на физических мобильных устройствах, полное сочетание языков/тем и аппаратное профилирование остаются. Автоматические проверки контраста не являются полной сертификацией WCAG.
