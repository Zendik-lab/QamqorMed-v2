# QamqorMed — Motion UI 5.0

## Реализация

Единая motion-система подключена к существующим React-компонентам. Backend, PostgreSQL, JWT, API, правила ролей и клинические обработчики в рамках Motion 5.0 не менялись. Прежние незакоммиченные изменения в checkout сохранены. Состояние предыдущего этапа интерфейса описано в `REDESIGN-4.md`.

Runtime dependencies остались React и React DOM. Для текущих коротких переходов достаточно CSS и нативного Web Animations API; дополнительная библиотека Motion for React не понадобилась. Общая логика собрана в двух модулях, а не повторяется в страницах.

### Параметры и API

| Параметр | Значение | Использование |
| --- | --- | --- |
| `--duration-fast` | 140 ms | Нажатие, результаты, выход панелей |
| `--duration-normal` | 220 ms | Страницы, меню, темы, календарь |
| `--duration-slow` | 360 ms | Однократное оформление auth |
| `--ease-standard` | cubic-bezier(.2,.7,.2,1) | Основные переходы |
| `--ease-exit` | cubic-bezier(.4,0,1,1) | Закрытие |
| `--motion-step` | 25 ms, на телефоне 0 | Первые четыре группы, максимум 75 ms задержки |

- `motion.js`: варианты `page`, `fade`, `results`, `panel`, `drawer`; управление отменой, завершением и reduced-motion; проверка позиции чата `isNearBottom`.
- `Motion.jsx`: `MotionRegion`, `useMotion` и `usePresence`. `replayKey` перезапускает только визуальный переход на том же DOM-элементе. React `key` для анимации форм не используется.
- `usePresence` сохраняет панель на время выхода, отменяет старый выход при повторном открытии. Закрывающиеся панели `inert`; запросы и действия не ждут анимации. Native dialog сохраняет модальность до окончания короткого выхода.
- `motion.css` подключён последним после существующих UI/account styles. Контент видим по умолчанию: отсутствие поддержки анимации не скрывает информацию.

Пример для нового списка:

```jsx
<MotionRegion replayKey={`${page}|${query}`} variant="results">
  <Results items={items} />
</MotionRegion>
```

Фильтры и поля ввода следует держать вне анимируемого списка. Обёртка должна оставаться на месте между изменениями состояния. Существующие loading/error/empty состояния сохраняются.

| Dashboard четырёх ролей | Ограниченный stagger первых четырёх блоков, короткое появление данных/списков, hover lift быстрых действий и метрик на устройствах с мышью. |
| Профили | Появление identity, редактора и формы безопасности, success/error feedback, переходы общих вкладок. Загрузка аватара не добавлялась: существующего API нет. |
| Календари | Переход содержимого day/week/month без движения отдельных ячеек; появление подробностей приёма; выбор даты и слота пациента; смена результатов после выбора даты. Высоты строк, расчёт времени и сортировка записей сохранены. |
| Документы и история | Переходы результатов при смене субъекта, категории и фильтров; появление timeline, tabs, preview и форм документов. Доступные индикаторы реальной загрузки сохранены. |
| Table | Единый переход контейнера при поиске, сортировке и пагинации. Ввод и фильтры не анимируются; ячейки отдельно не анимируются. |
| Feedback | Общие dialog/drawer и toast с входом/выходом; success/info по умолчанию 6 s, error/warning остаются до закрытия; hover/focus приостанавливает таймер. Skeleton использует opacity, spinner отражает реальное ожидание. |
| AI | Вход/выход окна, появление последних сообщений, press отправки, настоящий pending-индикатор. История следует за ответом только у нижней границы; при чтении старых сообщений позиция сохраняется. Draft сохраняется при закрытии окна. SSE/auth/tool workflow сохранён. |
| Темы и телефон | Короткие переходы цветов поверхностей и текста. Мобильный drawer использует общий механизм; stagger и декор уменьшены. Toast расположен выше нижней навигации. |

### Доступность и стоимость

`prefers-reduced-motion: reduce` отключает CSS animation/transition/smooth scroll. JS не запускает WAAPI при включённом предпочтении и отменяет уже запущенную анимацию при его изменении; ожидающий выход сразу завершается. Текст статусов, роли alert/status, disabled и busy не зависят от движения.

Общие варианты меняют только transform/opacity, без JS-циклов на каждый кадр. Геометрия анимируется только при намеренном desktop collapse; при переключении к мобильной навигации отступ меняется сразу. ResizeObserver ограничен навигацией, обработчики и анимации очищаются при размонтировании. Нет постоянного `will-change`, больших blur/filter или бесконечного декора. Повторяющиеся эффекты оставлены только для настоящего loading/pending.

На 320 px исправлен существующий `body min-width:320px`: при обычном Windows scrollbar он создавал лишние 15 px ширины. Теперь body занимает доступную область.

## Границы и оставшиеся проверки

1. Полный медицинский цикл с работающим Spring Boot, заполненными расписаниями, выдачей/скачиванием документов и настоящей Ollama ещё не проверен. Локальный UI-стенд не подтверждает серверные права или клинические операции.
2. Reduced-motion проверен unit-тестами и CSS override; переключение системного предпочтения в настоящей ОС/на физических мобильных устройствах в этом сеансе не проверялось. Полный screen-reader pass также остаётся.
3. Legacy локальные modal/drawer получили общие CSS entrance-эффекты. Плавный exit, native focus containment и общий механизм presence гарантируются для UI Dialog/Drawer; полная миграция старых локальных overlays остаётся отдельной работой редизайна.
4. Не выполнено аппаратное FPS-профилирование на слабых телефонах и больших клинических списках. Ограниченные transform/opacity эффекты уменьшают нагрузку, но не являются доказательством постоянных 60 FPS.
5. Более широкий Overhaul 4.0 всех dashboard/внутренних страниц не объявляется завершённым; его остаток описан в `REDESIGN-4.md`.

Справка по используемым браузерным API: [Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate), [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).
